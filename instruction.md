# Firmware Release Publisher

The firmware code-signing key was rotated. The existing publisher signs releases
with the revoked key, so the distribution gateway rejects them. Implement the
publisher at `/app/publisher/release-publisher.mjs`. It is run with:

```sh
cd /app
npm run report
```

Do not modify `/app/distribution-gateway/`, its data directory, the fixtures, or
the verifier. Interact with the gateway only through its documented HTTP API.

## Inputs and runtime artifacts

- Read `/app/fixtures/build_manifest.csv`.
- Create and maintain `/app/releases.duckdb` with DuckDB.
- Read the current signing key and certificate from
  `/app/keys/current/current.key.pem` and
  `/app/keys/current/current.cert.pem`.
- Do not use anything under `/app/keys/revoked/`.
- The gateway is available at `http://127.0.0.1:7070`.

## Reconcile the manifest with SQL

Import the CSV into DuckDB and use SQL to derive publishable bundles.

1. Collapse rows that are identical across **all eight CSV columns**.
2. A `WITHDRAWAL` cancels the `BUILD` whose `entry_id` equals its
   non-empty `supersedes_id`.
3. Ignore cancelled builds. A bundle is publishable only when it has at least
   one surviving `BUILD`.
4. For every publishable bundle, calculate its surviving build count
   (`artifact_count`) and sum of `size_bytes` (`total_bytes`).
5. Process bundles in ascending `bundle_id` order.

Do not hardcode bundle identifiers, counts, sizes, or output lines.

## Sign and publish

First request `GET /v1/signing-key/current`. Its `key_id` is the key identifier
you report. For each publishable bundle, make this release descriptor:

```json
{"artifact_count":<number>,"bundle_id":"<id>","total_bytes":<number>}
```

The descriptor must be UTF-8 JSON with object keys sorted lexicographically and
no insignificant whitespace. Sign those exact bytes with a detached PEM CMS
signature using OpenSSL and the current keypair. Submit `POST /v1/publications`
with this JSON body:

```json
{
  "descriptor": "<the exact canonical descriptor string>",
  "signature": "<detached PEM CMS signature>",
  "request_token": "token-<bundle_id>"
}
```

The gateway returns `{ publication_id, request_token, status: "PUBLISHED" }`.
Treat any non-success response or malformed receipt as an error.

## Persistence and output

Persist each successful bundle's request token, publication receipt, status,
key id, and descriptor in `/app/releases.duckdb`. On a later run, reuse the
stored receipt for an already published bundle; do not submit it again.

For every publishable bundle print exactly these two lines, with no diagnostic
output on stdout:

```text
BUNDLE <bundle_id> SIGNED KEY=<key_id>
BUNDLE <bundle_id> PUBLISHED RECEIPT=<publication_id> TOKEN=token-<bundle_id> STATUS=PUBLISHED
```

The second run must have byte-identical stdout and must not add gateway
publications. The receipt value is generated by the gateway and is intentionally
not fixed.
